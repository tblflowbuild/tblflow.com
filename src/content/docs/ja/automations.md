自動化は、ベースに紐づくワークフローです。1つのトリガーと、それに続くステップの並びで構成されます。サーバー側で実行されるため、タブを開いている人がいなくても動作します。

自動化は、**新規自動化** から作成するか、**AIで生成** に作りたい内容を書いて作成できます。AIが設定案を提案するので、エディターで内容を確認して調整してください。スイッチで自動化を有効または無効にできます。トリガーが設定されるまでは有効にできません。

## トリガー

| トリガー | 起動するタイミング |
| --- | --- |
| **レコードが作成されたとき** | 選んだテーブルに行が追加されたとき |
| **レコードが更新されたとき** | 選んだテーブルの行が変更されたとき |
| **レコードが条件に一致したとき** | 行がすべての条件（フィールド、演算子、値）を満たしたとき |
| **レコードが削除されたとき** | 行が削除されたとき |
| **フォームが送信されたとき** | テーブルのフォームが送信されたとき（特定のフォームビュー、またはすべて） |
| **ボタンがクリックされたとき** | テーブルのボタンフィールドがクリックされたとき（特定のフィールド、またはすべて） |
| **予定時刻に** | 選んだ間隔（分、時間、日、週、月）ごと |
| **Webhookを受信したとき** | エディターに表示されたURLにHTTP呼び出しが届いたとき |
| **新しいメールを受信したとき** | 接続済みのGmailアカウントの受信トレイに、新しい未読メールが届いたとき |
| **コネクターに新しい項目が現れたとき** | コネクターのリストに新しい項目が現れたとき |
| **インターフェースから** | ベースの生成済みインターフェースが自動化を実行したとき |

補足事項は次のとおりです。

- **予定時刻。** 予定時刻の自動化は、スペースのタイムゾーンで実行されます。スペースにタイムゾーンがない場合はUTCで実行されます。15分未満の間隔は、初期設定では拒否されます。
- **Webhook。** 呼び出しは `POST` で、ヘッダー `X-Webhook-Secret` を含める必要があります。シークレットはエディターで設定します。有効なシークレットがない呼び出しは拒否されます。受信した本文は、変数のルートから直接参照できます。
- **受信メール。** 受信トレイの新しい未読メールだけが自動化を起動します。有効化の時点ですでに届いていたメールは無視されます。Gmailアカウントは **コネクター** 画面で接続します。
- **トリガーの連鎖。** 監視しているテーブルに書き込むステップは、自動化を再びトリガーすることがあります。エンジンは、連続した5世代を超えるそのような連鎖を打ち切ります。ただし、そこに依存しないように自動化を設計するのが望ましいです。

## ステップ

**ステップを追加** メニューには、ステップが3つのグループに分かれて並んでいます。

| グループ | ステップ |
| --- | --- |
| AIで構築 | **スクリプトを実行**、**Slack**、**Microsoft Teams**、**メールを送信**、**AI生成**、**レコードの作成・更新・取得**、**HTTPリクエストを送信** |
| 手動で構築 | **レコードを作成**、**レコードを取得**、**レコードを更新**、**キーに基づいて作成または更新**、**AIフィールドを実行**、**今すぐ同期**、**ウェブサイトを操作** |
| ロジック | **条件を満たす場合**（「その場合」と「それ以外」の分岐）、**ループ（各要素について）** |

**APIに接続** ボタンは **接続済みAPIを呼び出す** ステップを追加します。このステップは、接続済みのサードパーティAPIの操作を、そのOpenAPIドキュメントを使って実行します。

エディターには、レコードの削除、待機、人による承認のステップはありません。書き込みの前に人の合意が必要な場合は、書き込みの承認を有効にした[エージェント](/ja/docs/ai-agents)を使ってください。

各ステップは、トリガーのデータと前のステップの出力を読み取ります。**変数を挿入** ボタンには、ワークフローのその時点で実際に利用できる値が表示されます。基本の形は、トリガーのレコードが `{{record.fields.<フィールドID>}}`、ステップの出力が `{{steps.<ステップID>.<パス>}}` です。`|` の後に追加したフィルターは値を変換します（日付、数値、リスト、既定値、大文字・小文字など）。エラーになったステップは実行を中断し、後続のステップは実行されません。

**メールを送信** ステップは、接続済みのGmailアカウントから送信できます。アカウントを選ばなければ、TblFlowの送信サービスから送信されます。

## テスト

**テストを実行** を押すと、トリガー用のサンプルデータを使って自動化を空実行します。各ステップの結果が表示されるウィンドウが開きます。「これはシミュレーションです。実際のデータは変更されていません」というメッセージがそれを示します。テストは、ステータス **テスト** として履歴に表示されます。

## 実行履歴

**実行履歴** ボタンには、自動化の実行が新しい順に並びます。各実行には、ステータス（**成功**、**エラー**、**実行中**、**テスト**のいずれか）、所要時間、開始時刻、トリガー、そして各ステップの種類、ステータス、メモが表示されます。履歴は直近50件の実行を保持します。履歴から再実行することはできません。修正後は、トリガーによって自動化を再度実行してください。

## 上限

月間の実行回数はプランによって異なります。実行は、トリガーが起動するたびに1回と数えられ、ステップの数には関係ありません。自動化が送信するメールは別に数えられます。

| プラン | 月間の実行回数 | 月間の自動化メール |
| --- | --- | --- |
| 無料 | 500 | 50 |
| Essential | 25,000 | 2,000 |
| チーム | 250,000 | 20,000 |
| Enterprise | 無制限 | 無制限 |

セルフホスト環境では、これらの上限は適用されません。エージェントの上限は、[AIエージェント](/ja/docs/ai-agents)のページで説明しています。

## 自動化かエージェントか

自動化は、あなたが書いた手順をそのとおりに実行します。同じ入力なら同じ経路をたどり、同じ結果になります。ルールが分かっているときに向いています。

[エージェント](/ja/docs/ai-agents)は、目標から自分でステップを決めます。ルールが内容に依存するとき、たとえば性質の異なる受信リクエストを振り分ける場合に向いています。両者は組み合わせられます。エージェントは、そのツールを使って自動化の一覧を取得したり、実行したりできます。ただし、書き込みは承認の対象になります。
