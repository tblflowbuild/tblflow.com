自動化は、ベースに紐づくワークフローです。1つのトリガーと、それに続くステップの並びで構成されます。タブを開いている人がいなくても、サーバー側で実行されます。

## トリガー

| トリガー | 起動するタイミング |
| --- | --- |
| レコード作成 | 監視対象のテーブルに行が追加されたとき |
| レコード更新 | 監視対象のフィールドの値が変わったとき |
| レコードが条件に一致 | 行がフィルタの範囲に入ったとき |
| Cron | 指定したスケジュール（cron式、ベースのタイムゾーン）で |
| Webhook | 生成されたURLにHTTP呼び出しが届いたとき |
| 手動 | 誰かがボタンフィールドをクリックしたとき |

「更新」トリガーを本当に必要なフィールドだけに絞ると、よくあるループを避けられます。監視しているテーブルに自動化自身が書き込み、再びトリガーされてしまうループです。

## ステップ

利用できるステップ：レコードの作成・更新・削除、レコードの検索、メール送信、URL呼び出し、条件分岐の実行、リストの反復処理、待機、承認の依頼、エージェントの呼び出し。

各ステップは、前のステップの出力を受け取ります。値は`{{step.field}}`で参照でき、エディターはワークフローのその時点で実際に存在するフィールドを候補として表示します。

## 人による承認

**承認**ステップは、実行を一時停止し、指定した人に通知します。承認されるとワークフローが再開し、却下されると停止し、設定したタイムアウトを過ぎると期限切れになります。

外部に働きかけるものの前には、必ず置いてください。顧客へのメール、課金されるAPI呼び出し、公開などです。社内で誤った自動化は修正できますが、顧客に対して誤った自動化は取り戻すのがはるかに困難です。

## 実行ログ

すべての実行は、トリガー、各ステップの入力と出力、失敗した場合はその理由とともに保存されます。失敗した実行は、原因を修正した後にログから再実行でき、すでに成功したステップは再実行されません。

## クォータ

月間の実行回数はプランによって異なり、Businessプラン以上およびセルフホスト時は無制限です。1回の実行とは1回のトリガーのことで、ステップ数は関係ありません。

## 自動化かエージェントか？

自動化は、あなたが書いた手順をそのとおりに実行します。同じ入力なら同じ経路をたどり、同じ結果になります。ルールが分かっているときに向いています。

[エージェント](/ja/docs/ai-agents)は、目標から自分でステップを決めます。ルールが内容に依存するとき、たとえば性質の異なる受信リクエストの振り分けに向いています。両者は組み合わせられます。自動化は、他のステップと並べてエージェントを1ステップとして呼び出せます。
