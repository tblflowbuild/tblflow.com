TblFlowのテーブルは、本物のPostgreSQLテーブルです。フィールドは本物のカラムです。そのため、UIから離れることがなくても、このページは役に立ちます。ここで選んだものが、そのままデータベースに存在するからです。

## フィールドの分類

**単純な値** — 1行テキスト、長文テキスト、数値、通貨、パーセント、日付、チェックボックス、評価、メール、電話、URL。入力したものをそのまま保存します。

**制約のある値** — 単一選択、複数選択、ユーザー。選択肢はフィールドに定義されるため、グループ化やフィルタが信頼できます。「進行中」の表記ゆれが共存することはありません。

**リレーショナル** — リンクレコード、ルックアップ、ロールアップ、条件付きロールアップ。詳しくは後述します。

**計算** — 数式（200以上の関数）、オートナンバー、作成日時、最終更新日時、作成者、最終更新者。編集はできず、書き込み時に再計算されます。

**アクティブ** — 添付ファイル、ボタン、AI。AIフィールドは、ベースに設定されたモデルを呼び出し、その回答をセルに書き込みます。

## 2つのテーブルをリンクする

**リンクレコード**フィールドは、2つのテーブルの間にリレーションを作成します。リレーションができると、次のことが可能になります。

- **ルックアップ**は、リンク先のテーブルからフィールドを取得します（連絡先の行に会社名を表示するなど）。
- **ロールアップ**は、リンクされたレコードを集計します（アカウントの案件の`SUM`、プロジェクトのタスクの`COUNT`など）。
- **条件付きロールアップ**は、一部のレコードに限って同じことを行います（ステージが「成約」の案件の`SUM`など）。

この3つはいずれも、元のデータが変わると再計算されます。外部のSQLクライアントから変更された場合も同様です。

## 数式

数式はフィールドに定義され、すべての行に適用されます。利用できる分類は、テキスト、数値、日付、論理、リンクされたレコードの集計です。

```
IF(
  AND({Stage} = "Won", {Amount} > 10000),
  "Key account",
  "Standard"
)
```

数式は副作用を持てません。他のテーブルへの書き込みやネットワーク呼び出しはできません。それには[自動化](/ja/docs/automations)が必要です。

## Postgresではどうなるか

各ベースはスキーマ、各テーブルは物理テーブル、各フィールドは型付きのカラムです。`psql`、ORM、BIツールを同じインスタンスに向ければ、データを直接読み取れます。エクスポートも、同期レイヤーも、レプリケーションの遅延もありません。

実用上の帰結として、`pg_dump`は他の場所でも使える完全なバックアップになります。ここでの「ロックインなし」とは、そういうことです。

## 知っておきたいこと

- フィールド名を変更しても変わるのはラベルだけで、数式が使う参照は変わらないため、何も壊れません。
- フィールドの型を変更すると変換が試みられ、失われる値がある場合は警告が表示されます。
- フィールドを削除するとカラムが削除されます。操作は記録されますが、ベースのゴミ箱を超えて元に戻すことはできません。
