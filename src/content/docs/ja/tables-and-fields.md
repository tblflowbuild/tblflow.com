TblFlowのテーブルは、本物のPostgreSQLテーブルです。フィールドは本物のカラムです。UIから離れなくても、このページは役に立ちます。ここで選んだものが、そのままデータベースの中に存在するからです。

## フィールドの種類

**タイプ**メニューには28種類のフィールド型があり、さらに**ルックアップ**と**条件付きルックアップ**の2つが加わります。フィールド型はプランによって変わりません。

**単純な値** — 1行テキスト、長文テキスト、メール、電話、URL、数値、日付、チェックボックス、評価。入力した内容をそのまま保存します。メール、電話、URLは有効な形式である必要があります。

**期間** — **期間**は1:30、1:30:00、1h 30mのいずれかの形式で表示されます。**時間計測**は、行ごと、担当者ごとに費やした時間を計測します。

**時間計測.** セルには合計時間が時間と分で表示され、フィールドの**秒を表示**オプションを有効にすると秒も表示されます。セル内に入力するものはありません。セルをダブルクリックするか（またはEnterキーを押すか）、レコードを開くと、タイマーにアクセスできます。**開始**で期間が始まり、**停止**で終了します。表示される合計は実行中は毎秒増え、停止時にフィールドの値が更新されます。期間は担当者ごとに、開始時刻とともに一覧表示されます。各担当者は自分の期間だけを削除でき（**この期間を削除**）、合計は再計算されます。担当者、行、フィールドごとに実行中の期間は1つだけです。タイマーの開始と停止にはレコードを編集する権限が必要です。読み取り権限のロールでは、ボタンは表示されませんが、合計と期間は見られます。

**制約のある値** — 単一選択、複数選択、ユーザー。選択肢はフィールドごとに定義されます。

**リレーション** — リンクレコード、ルックアップ、ロールアップ、条件付きルックアップ、条件付きロールアップ。下記を参照してください。

**計算** — 数式（200以上の関数）、オートナンバー、行ID、作成日時、最終更新日時、作成者、最終更新者。手入力はできません。

**アクティブ** — 添付ファイル、ボタン、AIフィールド、Canvas。AIフィールドは、他のフィールドの内容からセルの内容を生成します。Canvasフィールドは、行ごとにドキュメントライブラリへドキュメントを1つ作成します。

**書式.** **通貨**と**パーセント**は独立した型ではなく、**数値**型の書式です。**リング**や**バー**と同様に、値を表示する方法の一つです。同じように、**日付**と**日付と時刻**は**日付**型の2つの設定です。

テーブルの主フィールド（各レコードを識別するフィールド）が受け付ける型は一部だけです。例えば、添付ファイルやリンクレコードは使えません。

## 2つのテーブルをリンクする

**リンクレコード**フィールドは、2つのテーブルの間にリレーションを作成します。1対1、1対多、多対1、多対多から選べます。リンクは一方向にも双方向にもでき（**リンクテーブルに逆方向のリンクフィールドを作成**）、別のベースを指定することもできます。リレーションを設定すると、次のことができます。

- **ルックアップ**は、リンク先のテーブルのフィールドを取り込みます（連絡先の行に会社名を表示するなど）。
- **ロールアップ**は、リンクされたレコードを**SUM**や**COUNT**などの関数で集計します（アカウントの案件の合計、プロジェクトのタスク数など）。

**条件付きルックアップ**と**条件付きロールアップ**にはリンクは必要ありません。テーブルを選び、そのレコードを絞り込む条件を指定します（ステータスが「受注」の案件の合計など）。

これらのフィールドは、元になるデータが変わると再計算されます。

## 数式

数式はフィールドごとに書き、すべての行に適用されます。関数は、数値、テキスト、論理、日付と時刻、テーブル、システムの6つのグループに分かれています。数式は**ルックアップ**と**ロールアップ**のフィールドを読み取れますが、別のテーブルのフィールドを直接読むことはできません。

```
IF(
  AND({Statut} = "Gagné", {Montant} > 10000),
  "Compte clé",
  "Standard"
)
```

数式に副作用を持たせることはできません。別のテーブルへの書き込みも、ネットワーク呼び出しもできません。そのためには[オートメーション](/ja/docs/automations)が必要です。

## デフォルト値と検証

フィールドのパネルにある**デフォルト値**は、新しい行に初期値を入力します。1行テキスト、長文テキスト、数値、期間、電話、チェックボックス、ユーザー、単一選択、複数選択の各型で使えます。日付型では、代わりに**現在の日付を自動入力**を使います。

**フィールド値の検証ルール**は、2つのスイッチです。

- **一意の値のみ**：1行テキスト、長文テキスト、数値、期間、日付、メール、電話、URLの各型に対して有効です。
- **必須**：上記と同じ型に加え、選択、ユーザー、評価、時間計測、添付ファイル、リンクレコードの各型に対して有効です。この規則は、フィールドの作成時ではなく、既存のフィールドを編集して設定します。

どちらのルールも、**ルックアップ**型のフィールドには適用されません。

## Postgresでの実際の姿

各ベースはPostgreSQLのスキーマ、各テーブルは物理テーブル、各フィールドは1つのカラムになります。ベースの所有者は、ベースの**設計**ページから**読み取り専用のPostgresアクセス**を開き、`psql`、ORM、BIツールでデータを読み取れます。このアクセスは読み取りのみです。書き込みはすべてTblFlowを通じて行います。ホスト版では、Enterpriseプランでのみ利用できます。詳しくは[APIと開発者向け情報](/ja/docs/api-developers)を参照してください。

## 知っておくべき制限

- フィールド名を変更すると変わるのは表示ラベルだけです。数式は内部のフィールドIDを参照するため、何も壊れません。
- フィールドの型を変更すると、既存の値が変換されます。変換に時間がかかる場合やリンクフィールドに影響する場合は、**フィールドの変更を確認**ウィンドウに、対象のフィールドが先に表示されます。
- フィールドを削除すると、それに依存するフィールドの一覧が表示されるウィンドウが開きます。削除したフィールドはテーブルのごみ箱に移動し、保持期間中は値と一緒に復元できます。詳しくは[インポート、エクスポート、ごみ箱](/ja/docs/import-export-trash)を参照してください。
