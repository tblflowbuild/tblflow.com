CLI TblFlow керує вашими базами з термінала: читає й записує записи, імпортує та експортує CSV-файли, запускає відкриті автоматизації й агенти та підключає локальний MCP-клієнт (Claude Code, Cursor…) до ваших даних. Його опубліковано в npm під назвою `@tblflow/cli` за ліцензією MIT.

Потрібен Node.js 20 або новіший; сторонніх залежностей немає.

## Встановлення

```bash
npm install -g @tblflow/cli
tblflow --help
```

Без встановлення: `npx @tblflow/cli --help`.

## Вхід

### На вашому комп’ютері

```bash
tblflow login     # з’являється код, ви підтверджуєте його в браузері
tblflow whoami
tblflow logout    # видаляє локальну сесію й відкликає токен на сервері
```

Перш ніж підтвердити, переконайтеся, що код у терміналі збігається з кодом у браузері. Токени зберігаються в зв’язці ключів системи (macOS, Linux Secret Service). Якщо її немає, вони зберігаються в `~/.config/tblflow/credentials.json`, доступному лише вам, і CLI попередить вас про це.

### У безперервній інтеграції

Створіть **службовий токен** у TblFlow: Налаштування простору → Безпека й аудит → Службові облікові записи (див. [API і доступ для розробників](/uk/docs/api-developers)). Збережіть його в секретах вашого CI, а потім передайте як змінну середовища:

```bash
export TBLFLOW_TOKEN=...      # передається CI, ніколи не записується в репозиторій
tblflow bases
```

`TBLFLOW_TOKEN` має пріоритет над будь-якою збереженою сесією й ніколи не записується на диск. Щоб один раз зберегти токен на виділеному комп’ютері, прочитайте його зі стандартного введення:

```bash
printenv TBLFLOW_TOKEN | tblflow login --token -
```

`tblflow login --token <токен>` теж працює, але тоді токен залишається в історії оболонки та в списку процесів: CLI нагадає вам про це. Токен перевіряється на сервері перед збереженням і не з’являється в жодному виведенні чи повідомленні про помилку. `tblflow logout` забуває токен, збережений таким способом, але не відкликає його: відкликання виконується в налаштуваннях простору.

### Вибір сервера

За замовчуванням CLI звертається до `https://app.tblflow.com`. Для іншого сервера використовуйте `--host https://…` або змінну `TBLFLOW_URL`. HTTPS обов’язковий, окрім `localhost`.

## Команди

| Команда | Дія |
|---|---|
| `bases` | Простори й бази, до яких є доступ |
| `tables <baseId>` | Таблиці бази |
| `records list <tableId>` | `--take N` (щонайбільше 100), `--skip N`, `--fields a,b`, `--where "Поле=v"`, `--sort "Поле:desc"` |
| `records get <tableId> <recordId>` | Читає запис |
| `records create <tableId>` | `--data '<json>'` або `--file f.json` (щонайбільше 50) |
| `records update <tableId> [<recordId>]` | Оновлює один або кілька записів |
| `records delete <tableId> <recordId>…` | Попередній перегляд, далі видалення (у кошик) з `--confirm` |
| `import <tableId> <файл.csv>` | Додає рядки з CSV; `--dry-run` |
| `import --new-table <baseId> <файл.csv>` | Створює таблицю з CSV; `--name`, `--dry-run` |
| `export <tableId>` | CSV у стандартний вивід або `--out файл.csv`; `--view <viewId>` |
| `run automation <baseId> <workflowId>` | Запускає автоматизацію, відкриту її власником |
| `run agent <baseId> <agentId> <завдання…>` | Запускає агента, відкритого її власником |
| `api <МЕТОД> <шлях>` | Прямий виклик, лише шляхи `/api/`; для `DELETE` потрібен `--confirm` |
| `mcp serve` | Локальний MCP-сервер (stdio) |

Глобальні параметри:

| Параметр | Дія |
|---|---|
| `--json` | Виводить результат у JSON (крім `export` без `--out`, який записує CSV) |
| `--host <url>` | Сервер, який використовувати |
| `--no-browser` | Не відкривати браузер під час входу: адреса й код відображаються в терміналі |
| `-h`, `--help` | Довідка |
| `-v`, `--version` | Версія |

Коди завершення: 0 у разі успіху, 1 у разі помилки, 2 для помилки використання або якщо потрібне підтвердження.

### Створення таблиці з CSV

```bash
tblflow import --new-table <baseId> clients.csv --name "Clients" --dry-run
tblflow import --new-table <baseId> clients.csv --name "Clients"
```

`--dry-run` показує, що було б створено, нічого не записуючи.

## Підключення локального MCP-клієнта

`tblflow mcp serve` запускає локальний MCP-сервер на стандартному вводі й виводі. Оголосіть його в конфігурації вашого MCP-клієнта:

```json
{ "mcpServers": { "tblflow": { "command": "npx", "args": ["-y", "@tblflow/cli", "mcp", "serve"] } } }
```

Локальний сервер надає 7 інструментів із токеном вашої сесії:

| Інструмент | Дія |
|---|---|
| `list_workspaces` | Перелічує простори та їхні доступні бази |
| `list_tables` | Перелічує таблиці бази |
| `list_records` | Читає записи, щонайбільше 100 за виклик, із фільтрами й сортуванням |
| `get_record` | Читає запис за його ідентифікатором |
| `create_records` | Створює до 50 записів |
| `update_records` | Оновлює до 50 записів (змінюються лише надані поля) |
| `delete_records` | Без `confirm` показує попередній перегляд; з `confirm=true` надсилає записи в кошик |

Це скорочений набір: він не охоплює імпорт, статистику, створення таблиць і автоматизації. Віддалений MCP-сервер пропонує 27 інструментів.

Щоб підключити Claude (веб, десктоп або мобільний застосунок) без жодного встановлення, скористайтеся натомість віддаленим MCP-сервером: див. посібник [MCP-сервер](/uk/docs/mcp-server).
