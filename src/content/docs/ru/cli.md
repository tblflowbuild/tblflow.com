TblFlow CLI управляет вашими базами из терминала: читает и записывает записи, импортирует и экспортирует CSV, запускает открытые для доступа автоматизации и агентов и подключает локальный MCP-клиент (Claude Code, Cursor…) к вашим данным. Он опубликован в npm под именем `@tblflow/cli` и распространяется по лицензии MIT.

Ему нужен Node.js 20 или новее, сторонних зависимостей у него нет.

## Установка

```bash
npm install -g @tblflow/cli
tblflow --help
```

Без установки: `npx @tblflow/cli --help`.

## Вход

### На вашем компьютере

```bash
tblflow login     # выводится код, вы подтверждаете его в браузере
tblflow whoami
tblflow logout    # удаляет локальную сессию и отзывает токен на сервере
```

Перед подтверждением убедитесь, что код в терминале совпадает с кодом в браузере. Токены хранятся в связке ключей системы (macOS, Linux Secret Service). Если она недоступна, они сохраняются в `~/.config/tblflow/credentials.json`, файле, доступном только вам, и CLI предупреждает вас об этом.

### В непрерывной интеграции

Создайте **сервисный токен** в TblFlow: Настройки пространства → Безопасность и аудит → Сервисные аккаунты. Сохраните его в секретах вашей CI, затем передайте через переменную окружения:

```bash
export TBLFLOW_TOKEN=...      # подставляется CI, никогда не записывается в репозиторий
tblflow bases
```

`TBLFLOW_TOKEN` имеет приоритет над любой сохранённой сессией и никогда не записывается на диск. Чтобы один раз сохранить токен на выделенной машине, прочитайте его со стандартного ввода:

```bash
printenv TBLFLOW_TOKEN | tblflow login --token -
```

`tblflow login --token <токен>` тоже работает, но тогда токен остаётся в истории оболочки и в списке процессов: CLI напоминает об этом. Токен проверяется на сервере перед сохранением и не появляется ни в одном выводе или сообщении об ошибке. `tblflow logout` забывает сохранённый таким образом токен, но не отзывает его: отзыв выполняется в настройках пространства.

### Выбор сервера

По умолчанию CLI обращается к `https://app.tblflow.com`. Для другого сервера используйте `--host https://…` или переменную `TBLFLOW_URL`. HTTPS обязателен, кроме `localhost`.

## Команды

| Команда | Действие |
|---|---|
| `bases` | Доступные пространства и базы |
| `tables <baseId>` | Таблицы базы |
| `records list <tableId>` | `--take N` (не более 100), `--skip N`, `--fields a,b`, `--where "Поле=v"`, `--sort "Поле:desc"` |
| `records get <tableId> <recordId>` | Читает запись |
| `records create <tableId>` | `--data '<json>'` или `--file f.json` (не более 50) |
| `records update <tableId> [<recordId>]` | Обновляет одну или несколько записей |
| `records delete <tableId> <recordId>…` | Предварительный просмотр, затем удаление (корзина) с `--confirm` |
| `import <tableId> <файл.csv>` | Добавляет строки из CSV; `--dry-run` |
| `import --new-table <baseId> <файл.csv>` | Создаёт таблицу из CSV; `--name`, `--dry-run` |
| `export <tableId>` | CSV в стандартный вывод или `--out файл.csv`; `--view <viewId>` |
| `run automation <baseId> <workflowId>` | Запускает автоматизацию, открытую её владельцем |
| `run agent <baseId> <agentId> <задача…>` | Запускает агента, открытого его владельцем |
| `api <МЕТОД> <путь>` | Прямой вызов, только пути `/api/`; для `DELETE` нужен `--confirm` |
| `mcp serve` | Локальный MCP-сервер (stdio) |

`--json` работает со всеми командами. Коды завершения: 0 при успехе, 1 при ошибке, 2 при ошибке использования или когда требуется подтверждение.

### Создание таблицы из CSV

```bash
tblflow import --new-table <baseId> clients.csv --name "Clients" --dry-run
tblflow import --new-table <baseId> clients.csv --name "Clients"
```

`--dry-run` показывает, что было бы создано, ничего не записывая.

## Подключение локального MCP-клиента

`tblflow mcp serve` запускает локальный MCP-сервер на стандартном вводе и выводе. Укажите его в конфигурации вашего MCP-клиента:

```json
{ "mcpServers": { "tblflow": { "command": "npx", "args": ["-y", "@tblflow/cli", "mcp", "serve"] } } }
```

Чтобы подключить Claude (веб, компьютер или мобильное приложение) без установки, используйте удалённый MCP-сервер: см. руководство [MCP-сервер](/ru/docs/mcp-server).
