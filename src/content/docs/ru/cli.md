TblFlow CLI управляет вашими базами из терминала: читает и записывает записи, импортирует и экспортирует CSV, запускает открытые для доступа автоматизации и агентов и подключает локальный MCP-клиент (Claude Code, Cursor…) к вашим данным. Он опубликован в npm под именем `@tblflow/cli` и распространяется по лицензии MIT.

Ему нужен Node.js 20 или новее, сторонних зависимостей у него нет.

## Установка

```bash
npm install -g @tblflow/cli
tblflow --help
```

Без установки: `npx @tblflow/cli --help`.

## Вход

### На вашем компьютере

```bash
tblflow login     # выводится код, вы подтверждаете его в браузере
tblflow whoami
tblflow logout    # удаляет локальную сессию и отзывает токен на сервере
```

Перед подтверждением убедитесь, что код в терминале совпадает с кодом в браузере. Токены хранятся в системном хранилище ключей (macOS, Linux Secret Service). Если его нет, они сохраняются в `~/.config/tblflow/credentials.json`, доступном для чтения только вам, и CLI вас об этом предупредит.

### В непрерывной интеграции

Создайте **сервисный токен** в TblFlow: Настройки пространства → Безопасность и аудит → Сервисные аккаунты (см. [API и доступ для разработчиков](/ru/docs/api-developers)). Сохраните его в секретах вашей CI, затем передайте его через переменную окружения:

```bash
export TBLFLOW_TOKEN=...      # передаётся CI, никогда не записывается в репозиторий
tblflow bases
```

`TBLFLOW_TOKEN` имеет приоритет над любой сохранённой сессией и никогда не записывается на диск. Чтобы сохранить токен один раз на выделенной машине, передайте его через стандартный ввод:

```bash
printenv TBLFLOW_TOKEN | tblflow login --token -
```

`tblflow login --token <токен>` тоже работает, но тогда токен остаётся в истории оболочки и в списке процессов: CLI напоминает об этом. Токен проверяется на сервере перед сохранением и не появляется ни в одном выводе или сообщении об ошибке. `tblflow logout` удаляет токен, сохранённый таким способом, но не отзывает его: отзыв выполняется в настройках пространства.

### Выбор сервера

По умолчанию CLI обращается к `https://app.tblflow.com`. Для другого сервера используйте `--host https://…` или переменную `TBLFLOW_URL`. HTTPS обязателен, кроме `localhost`.

## Команды

| Команда | Действие |
|---|---|
| `bases` | Пространства и базы, доступные вам |
| `tables <baseId>` | Таблицы базы |
| `records list <tableId>` | `--take N` (не более 100), `--skip N`, `--fields a,b`, `--where "Поле=значение"`, `--sort "Поле:desc"` |
| `records get <tableId> <recordId>` | Читает запись |
| `records create <tableId>` | `--data '<json>'` или `--file f.json` (не более 50) |
| `records update <tableId> [<recordId>]` | Обновляет одну или несколько записей |
| `records delete <tableId> <recordId>…` | Предварительный просмотр, затем удаление (в корзину) с `--confirm` |
| `import <tableId> <файл.csv>` | Добавляет строки из CSV; `--dry-run` |
| `import --new-table <baseId> <файл.csv>` | Создаёт таблицу из CSV; `--name`, `--dry-run` |
| `export <tableId>` | CSV в стандартный вывод или `--out файл.csv`; `--view <viewId>` |
| `run automation <baseId> <workflowId>` | Запускает автоматизацию, открытую её владельцем |
| `run agent <baseId> <agentId> <задача…>` | Запускает агента, открытого его владельцем |
| `api <МЕТОД> <путь>` | Прямой вызов, только пути `/api/`; для `DELETE` нужен `--confirm` |
| `mcp serve` | Локальный MCP-сервер (stdio) |

Глобальные параметры:

| Параметр | Действие |
|---|---|
| `--json` | Выводит результат в JSON (кроме `export` без `--out`, который записывает CSV) |
| `--host <url>` | Сервер для использования |
| `--no-browser` | Не открывать браузер при входе: адрес и код выводятся в терминал |
| `-h`, `--help` | Справка |
| `-v`, `--version` | Версия |

Коды выхода: 0 при успехе, 1 при ошибке, 2 при ошибке использования или когда требуется подтверждение.

### Создание таблицы из CSV

```bash
tblflow import --new-table <baseId> clients.csv --name "Клиенты" --dry-run
tblflow import --new-table <baseId> clients.csv --name "Клиенты"
```

`--dry-run` показывает, что было бы создано, ничего не записывая.

## Подключение локального MCP-клиента

`tblflow mcp serve` запускает локальный MCP-сервер на стандартном вводе и выводе. Объявите его в конфигурации вашего MCP-клиента:

```json
{ "mcpServers": { "tblflow": { "command": "npx", "args": ["-y", "@tblflow/cli", "mcp", "serve"] } } }
```

Локальный сервер предоставляет 7 инструментов с токеном вашей сессии:

| Инструмент | Действие |
|---|---|
| `list_workspaces` | Список пространств и их баз, доступных вам |
| `list_tables` | Список таблиц базы |
| `list_records` | Чтение записей, не более 100 за вызов, с фильтрами и сортировкой |
| `get_record` | Чтение записи по её идентификатору |
| `create_records` | Создание до 50 записей |
| `update_records` | Обновление до 50 записей (меняются только переданные поля) |
| `delete_records` | Без `confirm` показывает предварительный просмотр; с `confirm=true` отправляет записи в корзину |

Это сокращённый набор: в него не входят импорт, статистика, создание таблиц и автоматизации. Удалённый MCP-сервер предлагает 27 инструментов.

Чтобы подключить Claude (веб, компьютер или мобильное приложение) без установки, используйте удалённый MCP-сервер: см. руководство [MCP-сервер](/ru/docs/mcp-server).
