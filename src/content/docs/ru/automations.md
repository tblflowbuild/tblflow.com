Автоматизация — это рабочий процесс, привязанный к базе: один триггер, затем последовательность шагов. Она выполняется на сервере, в том числе когда ни у кого не открыта вкладка.

## Триггеры

| Триггер | Срабатывает, когда |
| --- | --- |
| Запись создана | в отслеживаемую таблицу добавлена строка |
| Запись обновлена | значение отслеживаемого поля изменилось |
| Запись соответствует условию | строка попадает в область фильтра |
| Cron | по заданному расписанию (выражение cron, часовой пояс базы) |
| Вебхук | HTTP-вызов приходит на сгенерированный URL |
| Вручную | кто-то нажимает поле «Кнопка» |

Если ограничить триггер «обновлена» теми полями, которые вам действительно важны, можно избежать классической петли: автоматизация пишет в отслеживаемую таблицу и сама себя запускает снова.

## Шаги

Доступные шаги: создать / обновить / удалить запись, найти записи, отправить письмо, вызвать URL, выполнить условную ветвь, перебрать список, подождать, запросить утверждение, вызвать агента.

Каждый шаг получает результат предыдущих. Значение вы указываете как `{{step.field}}`, а редактор предлагает поля, которые действительно существуют в этой точке рабочего процесса.

## Утверждение человеком

Шаг **Утверждение** приостанавливает запуск и уведомляет назначенных вами людей. Рабочий процесс продолжается, если запрос принят, останавливается, если отклонён, и истекает по заданному вами тайм-ауту.

Ставьте его перед всем, что обращается во внешний мир: письмо клиенту, платный вызов API, публикация. Ошибку автоматизации внутри компании можно исправить; ошибку, допущенную перед клиентом, исправить гораздо труднее.

## Журнал запусков

Каждый запуск сохраняется вместе с триггером, входом и выходом каждого шага и причиной любого сбоя. Неудавшийся запуск можно повторить из журнала после устранения причины, не выполняя заново уже успешные шаги.

## Квоты

Число запусков в месяц зависит от тарифа; начиная с тарифа Business и при самостоятельном хостинге оно не ограничено. Один запуск — это один триггер, сколько бы шагов он ни содержал.

## Автоматизация или агент?

Автоматизация выполняет написанную вами последовательность: тот же вход, тот же путь, тот же результат. Это то, что нужно, когда правило известно.

[Агент](/ru/docs/ai-agents) сам определяет свои шаги по цели. Это то, что нужно, когда правило зависит от содержимого — например, при сортировке разнородных входящих обращений. Одно с другим сочетается: автоматизация может вызывать агента как один из шагов.
