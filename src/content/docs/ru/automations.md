Автоматизация — это рабочий процесс, привязанный к базе: один триггер, затем последовательность шагов. Она выполняется на сервере, в том числе когда ни у кого не открыта вкладка.

Создать её можно кнопкой **Новая автоматизация** или описав нужное словами через **Сгенерировать с ИИ**: ИИ предложит конфигурацию, которую вы проверяете и корректируете в редакторе. Переключатель включает или выключает автоматизацию. Включить её нельзя, пока не настроен её триггер.

## Триггеры

| Триггер | Срабатывает, когда |
| --- | --- |
| **Когда запись создана** | в выбранную таблицу добавлена строка |
| **Когда запись изменена** | строка выбранной таблицы изменена |
| **Когда запись соответствует условиям** | строка выполняет все ваши условия (поле, оператор, значение) |
| **Когда запись удалена** | строка удалена |
| **Когда форма отправлена** | отправлена форма таблицы (конкретное представление формы или все) |
| **Когда нажата кнопка** | кто-то нажимает поле «Кнопка» таблицы (конкретное поле или все) |
| **По расписанию** | через выбранный интервал: минуты, часы, дни, недели или месяцы |
| **Когда получен вебхук** | на URL, показанный в редакторе, приходит HTTP-вызов |
| **Когда получено новое письмо** | в папку «Входящие» подключённого аккаунта Gmail приходит новое непрочитанное письмо |
| **Новый элемент в коннекторе** | в списке коннектора появляется новый элемент |
| **Из интерфейса** | сгенерированный интерфейс базы запускает автоматизацию |

Некоторые уточнения:

- **Расписание.** Запланированные автоматизации выполняются в часовом поясе пространства, а если он не задан — в UTC. Интервал короче 15 минут по умолчанию не принимается.
- **Вебхук.** Вызов выполняется методом `POST` и должен содержать заголовок `X-Webhook-Secret`. Секрет задаётся в редакторе; без правильного секрета вызов отклоняется. Полученное тело доступно непосредственно в корне переменных.
- **Получено письмо.** Автоматизацию запускают только новые непрочитанные письма во «Входящих»; письма, которые уже были там в момент включения, пропускаются. Аккаунт Gmail подключается на экране **Коннекторы**.
- **Цепочки срабатываний.** Шаг, который пишет в таблицу, за которой автоматизация следит, может снова её запустить. Движок прерывает такую цепочку после пяти последовательных поколений, но лучше строить автоматизацию так, чтобы она от этого не зависела.

## Шаги

Меню **Добавить шаг** объединяет шаги в три группы.

| Группа | Шаги |
| --- | --- |
| Создание с помощью ИИ | **Выполнить скрипт**, **Slack**, **Microsoft Teams**, **Отправить письмо**, **Генерация ИИ**, **Создание, обновление и получение записей**, **Отправить HTTP-запрос** |
| Создание вручную | **Создать запись**, **Получить записи**, **Обновить запись**, **Создать или обновить по ключу**, **Выполнить поле ИИ**, **Синхронизировать сейчас**, **Управлять веб-сайтом** |
| Логика | **Если условия выполнены** (ветки «Тогда» и «Иначе»), **Цикл (для каждого)** |

Кнопка **Подключить API** добавляет шаг **Вызвать подключённый API**, который выполняет операцию стороннего API, подключённого через его документацию OpenAPI.

В редакторе нет шага удаления записи, ожидания или согласования с человеком. Если нужно, чтобы человек подтвердил запись перед её выполнением, используйте [агента](/ru/docs/ai-agents) с подтверждением записей.

Каждый шаг читает данные триггера и результаты предыдущих шагов. Кнопка **Вставить переменную** предлагает только те значения, которые реально доступны в этой точке рабочего процесса. Базовые формы: `{{record.fields.<идентификатор поля>}}` для записи триггера и `{{steps.<идентификатор шага>.<путь>}}` для результата шага. Фильтр, добавленный после `|`, преобразует значение (дата, число, список, значение по умолчанию, регистр). Если шаг завершился с ошибкой, выполнение прерывается: следующие шаги не запускаются.

Шаг **Отправить письмо** может отправлять от имени подключённого аккаунта Gmail; если аккаунт не выбран, письмо уходит через службу отправки TblFlow.

## Тестирование

Кнопка **Запустить тест** прогоняет автоматизацию без последствий, с примерными данными для триггера. В окне показан результат каждого шага. Сообщение «Это симуляция — реальные данные не изменены» напоминает об этом. Тест появляется в истории со статусом **Тест**.

## История запусков

Кнопка **История запусков** показывает запуски автоматизации, сначала самые свежие. У каждого указаны статус (**Успех**, **Ошибка**, **Выполняется** или **Тест**), длительность, время начала, триггер и, для каждого шага, тип, статус и примечание. В истории хранятся последние 50 запусков. Повторного запуска из истории нет: после исправления запустите автоматизацию снова через её триггер.

## Квоты

Число запусков в месяц зависит от тарифа. Каждое срабатывание считается одним запуском, независимо от количества шагов. Письма, отправленные автоматизациями, учитываются отдельно.

| Тариф | Запуски в месяц | Письма автоматизаций в месяц |
| --- | --- | --- |
| Бесплатный | 500 | 50 |
| Essential | 25 000 | 2 000 |
| Team | 250 000 | 20 000 |
| Enterprise | без ограничений | без ограничений |

При самостоятельном размещении эти лимиты не применяются. Квоты агентов описаны на странице [Агенты ИИ](/ru/docs/ai-agents).

## Автоматизация или агент?

Автоматизация выполняет написанную вами последовательность шагов: тот же вход, тот же путь, тот же результат. Это подходит, когда правило известно заранее.

[Агент](/ru/docs/ai-agents) сам выбирает шаги по заданной цели. Это подходит, когда правило зависит от содержимого — например, для сортировки разнородных входящих запросов. Их можно сочетать: агент может с помощью своих инструментов перечислять ваши автоматизации и запускать их, при условии подтверждения записей.
