Агент — это исполнитель, привязанный к базе. У него есть инструкции, набор инструментов и память, а по умолчанию каждая его запись ждёт вашего согласия.

Профиль агента состоит из пяти вкладок: **Инструкции**, **Задания**, **Навыки**, **Знания** и **Память**.

## Выбор модели

Поставщики и их ключи настраиваются для каждого пространства в **Настройках ИИ пространства**. Изменять их может только владелец пространства. Ключи зашифрованы при хранении и после сохранения больше не отображаются в открытом виде.

Среди доступных поставщиков: OpenAI, Anthropic, Google, Azure, Cohere, Mistral, DeepSeek, xAI, Amazon Bedrock, OpenRouter, любая конечная точка, совместимая с OpenAI, а также локальные модели через Ollama и LM Studio. Добавленные вами ключи складываются с ключами экземпляра, если только вы не отключите **Использовать модели экземпляра по умолчанию**.

В профиле агента выпадающий список **Модель** позволяет назначить ему собственную модель. Без выбора агент использует модель чата по умолчанию из настроек ИИ.

## Определение области действия

Область действия агента определяют три вещи.

- **Его база.** Агент не читает и не записывает таблицы другой базы: таблица, которой нет в его базе, отклоняется.
- **Его инструменты.** Вкладка **Навыки** перечисляет действия, которые агент может выполнять. Отключённый инструмент не предлагается модели, поэтому она не может его вызвать. Большинство инструментов для записей, таблиц и комментариев включены по умолчанию. Инструменты, которые обращаются к внешним сервисам или создают файлы, отключены по умолчанию и включаются по одному: поиск в Интернете, создание файлов Excel, Word, PowerPoint и PDF, запуск навыка или кода, e-mail, Slack, Microsoft Teams, GitHub, календарь, Drive и SharePoint, повторное воспроизведение навыка браузера. Делегирование другим агентам включено по умолчанию только для агента-оркестратора.
- **Его подключения.** Учётные записи, подключённые в разделе **Коннекторы**, работают на ваших агентов. Когда агент никто не запускает (по расписанию, по триггеру), используются учётные записи его создателя. Также можно добавить агенту серверы MCP.

Чтобы ограничить то, что агент может делать, уберите инструменты, которые ему не нужны. Агенту сортировки обращений в поддержку незачем отправлять e-mail или удалять записи.

## Подтверждение записей

Настройка **Подтверждение записей** включена по умолчанию, отдельно для каждого агента. Пока она активна, инструмент с реальным эффектом не выполняется: агент приостанавливается и запрашивает ваше согласие. Это касается, в частности, создания, изменения и удаления записей, создания таблиц, полей и представлений, комментариев, отправки e-mail или сообщений, запуска автоматизации, выполнения кода или навыка и записи в память.

Ответьте **Одобрить** или **Отклонить** (с необязательной причиной). Ожидающие запросы находятся на странице **Согласования** базы, доступной по ссылке **Посмотреть ожидающие согласования**. Без ответа запрос истекает через 7 дней, и действие не выполняется.

Отключайте эту настройку только после того, как увидите ошибки агента. После отключения агент пишет сам, и это касается всех его записей: настройка не задаётся для каждой таблицы отдельно.

## Память

Вкладка **Память** включает или отключает память агента, которая состоит из двух разделов:

| Раздел | Содержание |
| --- | --- |
| Недавние | краткосрочные воспоминания о недавней работе, хранятся 7 дней; сохраняются 50 самых новых, а 5 самых новых передаются агенту в начале задачи |
| Предпочтения | указания, данные людьми, в виде пары ключ и значение, передаются агенту при каждой задаче |

Когда агент запоминает сведения, из них могут быть извлечены сущности и связи в граф пространства, который агент запрашивает инструментом **Поиск в памяти**. Поэтому память — не история переписки: обмены хранятся отдельно, в истории.

**Посмотреть воспоминания** открывает список воспоминаний агента. Редакторы базы могут **Исправить** или **Стереть** воспоминание: если агент запомнил что-то неверное, исправляйте запись, а не инструкции.

## Навыки

Навык — это именованный блок инструкций, при необходимости с прилагаемым скриптом, который может использовать агент. Он может быть личным (аккаунт) или общим в пространстве. Доступны агенту навыки его создателя и навыки пространства; каждый по умолчанию отключён и включается для агента на вкладке **Навыки**. Запуск скрипта навыка выполняется через инструмент **Выполнить скрипт навыка**, который тоже отключён по умолчанию.

## Триггеры

Вкладка **Задания** показывает, когда агент запускается.

| Триггер | Как работает |
| --- | --- |
| Упоминание | агент анализирует запись и отвечает, когда его упоминают у записи (переключатель) |
| Личное сообщение | агент отвечает на отправленные ему сообщения (переключатель) |
| **Запустить агента** | запуск по требованию |
| По расписанию | по повторяющемуся графику или по собственному выражению cron; интервал короче 15 минут отклоняется по умолчанию |
| Автоматизация | при создании или изменении записи в таблице |
| Входящий webhook | HTTP-вызов запускает агента |

Триггер по записи срабатывает только если подтверждение записей отключено: пока оно обязательно, триггер неактивен, так как при автоматическом запуске нельзя запросить согласие человека. Расписание и webhook работают с подтверждением: запрос на согласие появляется в согласованиях.

## Квоты

Каждый запуск агента учитывается за месяц, независимо от того, запущен ли он вручную, по расписанию или по триггеру.

| Тариф | Запуски агентов в месяц |
| --- | --- |
| Бесплатный | 100 |
| Essential | 5 000 |
| Team | 50 000 |
| Enterprise | без ограничений |

На самостоятельно размещённом экземпляре эти лимиты не применяются. Кроме того, использование ИИ подчиняется другим лимитам, зависящим от тарифа. Квоты [автоматизаций](/ru/docs/automations) учитываются отдельно.

## История

Каждый запуск сохраняется как беседа, с вызовами инструментов агента, их параметрами и результатами. История бесед доступна из чата агента.

## Рекомендации

- Одна цель на агента. Агент, который «ведёт CRM», ошибается размыто; три узких агента ошибаются понятно.
- Оставляйте подтверждение записей включённым в начале и отключайте его только после того, как увидите характер ошибок агента.
- Включайте только инструменты, необходимые для задачи агента.
