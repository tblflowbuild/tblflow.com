Агент — это автономный исполнитель, привязанный к базе. У него есть цель, набор инструментов и память, а результатом его работы становятся предложения, а не прямые записи.

## Выбор поставщика модели

Модель настраивается для каждой базы с вашими собственными API-ключами: OpenAI, Anthropic, Google Gemini, Azure OpenAI, DeepSeek, Mistral, Groq, Cohere, любая OpenAI-совместимая конечная точка, а также локальные модели через Ollama и LM Studio.

При самостоятельном хостинге с локальной моделью данные базы не покидают вашу инфраструктуру.

## Настройка области доступа

Область доступа — самое важное для безопасности. Агент получает только те инструменты, которые соответствуют заявленному намерению: таблица, интерфейс, автоматизация, агент, приложение, тестовые данные. Остальных инструментов в его схеме нет, поэтому он не может их вызвать, а каждый инструмент заново проверяет собственные права при выполнении.

Ограничивайте и доступные таблицы. Агенту сортировки обращений в поддержку нечего делать в таблице зарплат.

## Предложения

Когда агент хочет изменить структуру или данные, он формирует **предложение**: предварительный просмотр изменения с идентификатором. Пока вы его не примете, ничего не записывается.

Для малорисковых задач (обогащение поля, применение метки) можно разрешить прямую запись в отдельные таблицы. Решайте это для каждой таблицы отдельно, но никогда не для всех сразу.

## Память

Память агента — это граф сущностей и связей, извлечённых из его прошлых запусков, а не журнал разговоров. Для каждой задачи загружаются только нужные фрагменты: агент помнит, а стоимость контекста не растёт безгранично.

Память можно просматривать и редактировать. Если агент усвоил что-то неверное, вы исправляете запись, а не промпт.

## Расписание

Агент может запускаться по требованию, по расписанию (cron) или вызываться как шаг внутри [автоматизации](/ru/docs/automations). Число ежемесячных запусков агентов зависит от тарифа.

## Практики, которые работают

- Одна цель на агента. Агент, который «ведёт CRM», ошибается расплывчато; три узких агента ошибаются понятно.
- Начинайте с предложений для всего и переходите к прямой записи, только когда увидите, как выглядят его ошибки.
- Сохраняйте журнал: каждый запуск хранит свой план, вызовы инструментов и записи.
