Коннектор соединяет TblFlow с внешним сервисом: с аккаунтом (Gmail, Slack…), с API, доступным по ключу, или с базой PostgreSQL. Затем ваши столбцы, таблицы, автоматизации и агенты могут его использовать.

## Где они находятся

В базе откройте **Автоматизации**, затем вкладку **Коннекторы**. Два представления:

- **Ваши**: аккаунты, API и базы данных, которые уже подключены;
- **Découvrir**: то, что можно добавить, с поиском и категориями (Почта, CRM, Продуктивность…).

Кнопка **Создать с ИИ** создаёт коннектор по документации API. Эта страница её не описывает.

## Подключение

### Аккаунт (OAuth)

В разделе **Découvrir** нажмите кнопку **+** у сервиса (подсказка «Подключить», за которой следует название): откроется окно сервиса, где нужно разрешить доступ вашего аккаунта. Можно указать **Имя аккаунта**, чтобы его легче было узнать. Затем в панели коннектора доступны **Переподключить** и **Отключить**. Отключение останавливает всё, что использует аккаунт (автоматизации, столбцы, агенты), до повторного подключения.

Если на сервере нет OAuth-приложения для какого-то сервиса, он отображается в разделе **Не настроены (админ)**. Тогда администратор пространства может указать OAuth-приложение своей организации в зоне **Расширенные** окна подключения.

### API с ключом

Коннекторы API находятся в разделе **Каталог** на вкладке **Découvrir**. Коннектор API сначала устанавливается (**Установить**), затем подключается (**Подключить**): вы вставляете ключ и адрес своего аккаунта, если он требуется. TblFlow сразу проверяет, отвечает ли ключ.

Настройка **Используемый аккаунт** позволяет выбрать между **Общим аккаунтом** для всего пространства и **Аккаунтом каждого пользователя**. С общим аккаунтом все вызовы идут через один аккаунт, подключённый менеджером пространства.

### База PostgreSQL

Коннектор **PostgreSQL** читает таблицы существующей базы, только для чтения. Никакие записи не отправляются.

## Операции

Панель коннектора показывает раздел **Что он позволяет**. Каждая операция относится к одному из трёх видов:

| Вид | Значение |
|---|---|
| **Читать** | Читает одну запись по значению |
| **Список** | Возвращает список элементов |
| **Действовать** | Создаёт, изменяет или отправляет что-то в сервисе |

Кнопка **Тестировать** запускает операцию из панели. Операцию можно затем использовать в четырёх местах (раздел **Где использовать**): в подключённом столбце, в синхронизированной таблице, в автоматизации (шаг **Вызвать операцию**) или в агенте, который может вызывать операции как инструменты.

Для коннектора, установленного из каталога, настройка **Разрешить запись** по умолчанию отключена. Когда она отключена, операции, которые создают, изменяют или удаляют данные в сервисе, отклоняются везде (автоматизации, кнопки, агенты); чтение продолжает работать.

## Синхронизация в таблицу

Синхронизированная таблица импортирует список из сервиса и поддерживает его в актуальном состоянии: каждый элемент становится строкой.

1. Включите коннектор, затем откройте его панель, раздел **Где использовать** → **Синхронизированная таблица**.
2. Выберите базу, затем нажмите **Создать синхронизированную таблицу**.
3. Выберите **Коннектор** и **Список** (операцию, которая возвращает список). **Предпросмотр** показывает первые элементы.
4. Отметьте **Столбцы** (типы: Текст, Длинный текст, Число, Флажок, Дата, Ссылка, E-mail) и **Уникальный идентификатор**, по которому каждый элемент находится от одной синхронизации к другой.
5. Настройте **Синхронизацию**: каждые 15 минут, каждый час, каждые 6 часов, раз в день или вручную.
6. Выберите, что делать с **Пропавшими элементами** (**Сохранять строки** или **Удалять строки**), задайте **Максимальное число элементов** и **Режим**, затем нажмите **Создать таблицу**.

Режим **Инкрементальный** перечитывает только элементы, изменённые с последней синхронизации, а весь список — по умолчанию раз в 7 дней. Он принимается, только если коннектор объявляет его для этого списка. Режим **Полный** перечитывает весь список при каждой синхронизации. Без других настроек чтение останавливается на 5 000 элементах; максимум, который можно задать, — 50 000. Синхронизированная таблица содержит не более 100 столбцов. Если чтение остановлено ограничением, появляется соответствующее сообщение.

Меню **Синхронизация** таблицы показывает состояние и содержит **Синхронизировать сейчас**, **Пересинхронизировать всё** и **Остановить синхронизацию** (таблица и её строки сохраняются).

По умолчанию таблица доступна только для чтения. Опция **Отправлять изменения в API** предлагает **После подтверждения администратором базы** или **Автоматически, при каждом изменении**; для её работы запись должна быть разрешена для коннектора.

## Запуск автоматизации: «Новый элемент»

В [автоматизации](/ru/docs/automations) триггер **Новый элемент в коннекторе** запускает автоматизацию один раз для каждого нового элемента списка.

- Выберите коннектор, список, элементы которого имеют идентификатор, его параметры и частоту **Проверять**: 15 минут, 1 час, 6 часов или 1 день.
- При первом чтении уже существующие элементы запоминаются, и ничего не запускается. Автоматизация срабатывает только на элементы, появившиеся позже.
- Поля элемента читаются через `{{item.<путь>}}`.
- За одно чтение выполняется не более 50 запусков и обходится не более 5 страниц.

## Коннекторы в разделе Découvrir

### Аккаунты (OAuth)

| Аккаунт | Что показывает панель |
|---|---|
| Gmail | Поиск и чтение писем, отправка письма |
| Google Календарь | Список событий, создание события |
| Google Drive | Поиск файлов, чтение сведений о файле |
| Google Meet | Создание ссылки на встречу |
| Google Chat | Список пространств, публикация сообщения |
| Slack | Список каналов, чтение сообщений канала, отправка сообщения |
| GitHub | Список и чтение issues, создание issues, список pull requests, комментарий |
| Outlook | Список писем, отправка письма |
| Microsoft Teams | Список ваших команд и их каналов, чтение, публикация и ответы, создание встречи |
| Discord | Чтение вашего профиля, список ваших серверов |

### API с ключом

| Коннектор | Что позволяет | Что нужно указать |
|---|---|---|
| Make | Чтение ваших организаций, команд и сценариев, их состояния и blueprint (только чтение) | Токен API Make (области `scenarios:read` и `teams:read`) и адрес вашей зоны |
| n8n | Чтение ваших workflow и их выполнений в экземпляре n8n Cloud | Ключ API n8n и адрес вашего экземпляра |
| HubSpot | Чтение, поиск, создание и обновление контактов, компаний и сделок, а также их связывание | Токен частного приложения HubSpot |

Make, n8n и HubSpot также питают [карту процессов](/ru/docs/process-map).

### ClickUp (пока не в Découvrir)

Коннектор ClickUp существует, но он ещё проходит проверку на реальном аккаунте: он не появляется в **Découvrir**, где показываются только опубликованные коннекторы. В интерфейсе нет кнопки для его установки. Пока он не опубликован, не рассчитывайте на него для регулярного использования.

Он подключается с **личным токеном** ClickUp (начинается с `pk_`). В руководстве по подключению указано, где его создать: в ClickUp, ваш аватар, **Настройки**, **Приложения**, раздел **Токен API**. У токена нет областей: он действует с вашими правами во всех рабочих пространствах, к которым у вас есть доступ. Чтобы ограничить доступ, создавайте токен из гостевого аккаунта только в нужных рабочих пространствах.

| Вид | Операции |
|---|---|
| **Список** | Рабочие пространства; пространства рабочего пространства; папки пространства; списки папки; списки, расположенные прямо в пространстве, вне любой папки; задачи списка; участники списка |
| **Читать** | Одна задача, с её пользовательскими полями и при необходимости подзадачами |
| **Действовать** | Создать задачу в списке; изменить задачу или архивировать её (меняются только отправленные поля, пользовательские поля здесь не изменяются); комментировать задачу |

Три операции «Действовать» являются записью: они отклоняются, пока настройка **Разрешить запись** отключена, как и для других коннекторов из каталога. Задачи списка читаются страницами по 100, по умолчанию сначала самые новые.

TblFlow распределяет свои вызовы к ClickUp: не более 2 одновременно и не менее 600 мс между двумя вызовами. Это остаётся ниже лимита ClickUp в 100 запросов в минуту на токен, который применяется к его самым младшим тарифам.

Триггер **Новый элемент в коннекторе** (см. выше) работает со списком **Список задач списка**: автоматизация запускается для каждой новой задачи списка ClickUp.

## Необходимые права

| Действие | Роль в пространстве |
|---|---|
| Использовать коннектор, подключить свой аккаунт | Все роли |
| Создавать и изменять коннектор | Владелец, создатель, редактор |
| Установить из каталога | Владелец; создатель, если установка открыта |
| Удалить коннектор | Владелец, создатель |

Управление каталогом задаётся в пространстве: **Открыто (владельцы и создатели пространства)** или **По одобрению администратора пространства**. Во втором случае другие участники используют **Запросить установку**.

Создание синхронизированной таблицы требует права на создание таблицы в базе. Права ролей подробно описаны в [Права и роли](/ru/docs/permissions).

## Квота вызовов

Каждый тариф ограничивает количество реальных вызовов коннекторов API в месяц (ответы, отданные из кэша, не учитываются): Бесплатный 1 000, Essential 50 000, Team 500 000. См. [Тарифы и лимиты](/ru/docs/plans-limits).
