Эта страница проведёт вас от пустого аккаунта до базы, открытой для вашей команды. На это уйдёт около пяти минут.

## 1. Создать базу

В пространстве нажмите **Создать базу**. База объединяет таблицы, автоматизации и агентов; каждая таблица имеет собственные представления. Под капотом каждая база — это отдельная схема PostgreSQL.

Окно спросит, что вы хотите построить:

- **Описать приложение** — напишите, что вы отслеживаете («инструмент для управления расписанием занятий учебного центра»), затем нажмите **Сгенерировать приложение**. ИИ предложит схему, представления, интерфейс и автоматизации, которые вы подтверждаете по шагам. Для генерации в пространстве должен быть настроен ИИ: иначе кнопка станет **Подключить ИИ для генерации** и приведёт к настройкам. См. [Чат с ИИ](/ru/docs/ai-chat).
- **Начать с пустой базы** — база создаётся без генерации ИИ; таблицы вы добавляете потом сами.

В пространстве, где ещё нет ни одной базы, можно также нажать **Начать с шаблона**. Шаблон **Управление проектами** входит в галерею, поставляемую с TblFlow: он создаёт таблицы Проекты, Задачи (с подзадачами и зависимостями), Спринты и Люди, представления Канбан, Гант и Календарь, представление **Дашборд** (сетка, сгруппированная по статусу, с итогами) и две автоматизации, которые заполняют или очищают дату «Завершено» у задачи. Предусмотрены один проект, один спринт и пять примеров задач; их можно адаптировать или удалить. Файл **.tbl**, экспортированный из другой базы, загружается обратно в пространство кнопкой **Импорт**. См. [Импорт, экспорт и корзина](/ru/docs/import-export-trash).

### Добавить таблицу

В боковой панели базы кнопка добавления предлагает:

- **Новая таблица** — поля вы задаёте вручную;
- **Создать с помощью ИИ** — вы описываете таблицу, появляется предпросмотр, и ничего не создаётся, пока вы не нажмёте **Создать**;
- **Добавить из других источников** — импорт файла CSV, TSV или Excel либо ссылки на файл (**Ссылка (URL)**). Типы полей определяются по данным (опция **Автоматическое определение типов полей**), и их можно исправить до импорта. Ячейки, скопированные из электронной таблицы, можно также вставить в представление-сетку.

## 2. Настроить поля

Тип поля отличает базу от электронной таблицы. Задайте его правильно: от него зависят формулы, фильтры и автоматизации.

| Задача | Тип поля |
| --- | --- |
| Одно значение из фиксированного набора | Выбор одного варианта |
| Ссылка на другую таблицу | Связь с другой записью |
| Значение из связанной таблицы | Поиск |
| Агрегат по связанным записям | Сводка |
| Вычисление по каждой строке | Формула |

Типы полей не зависят от вашего тарифа. См. [Таблицы и поля](/ru/docs/tables-and-fields).

## 3. Открыть второе представление

Представление — это способ прочитать таблицу, а не её копия. Переключение между представлениями не дублирует данные.

Если в таблице есть поле статуса, добавьте представление **Канбан**, сгруппированное по этому статусу. Если в таблице есть даты, добавьте **Календарь** или **Гант**. Фильтры, сортировки и группировки сохраняются в каждом представлении. По умолчанию представление общее: если коллега изменит фильтр «Мои просроченные дела», изменение увидят все. Кнопка **Личный** ограничивает ваши настройки только вами. См. [Представления, фильтры и карточки](/ru/docs/views-and-filters).

## 4. Пригласить команду

Кнопка **Пригласить** на боковой панели базы открывает доступ; она доступна только ролям, которые могут редактировать базу. Каждый получает роль для базы: создатель, редактор, комментатор или читатель (роль владельца назначается на уровне пространства). Персональные роли также можно задать для базы или таблицы. Чтобы опубликовать представление или открыть его за пределами команды, см. [Общий доступ и публикация](/ru/docs/sharing-publishing). См. [Разрешения и роли](/ru/docs/permissions).

Редактирование совместное и происходит в реальном времени: два человека могут одновременно менять одну таблицу, а активная ячейка каждого участника отмечается в сетке.
