A TblFlow base is not only browsable in the grid: it can be published as a real application, with its own pages, a public or invitation-only link, and a domain name of your own. This page covers the two ways to build one.

## Option 1 — describe it to the AI

In the base's chat panel, choose the **Full application** mode, then describe what you want: "A CRM with a dashboard, the list of accounts and the opportunity pipeline as a Kanban." Generation proceeds in stages: the tables, their relations, then the interface, the automations, the views and sample data, and finally an AI agent. Each stage produces proposals that you accept before moving on, and you can edit the current proposal as long as none has been accepted. Nothing is published until you click **Publish**.

## Option 2 — build it in the editor

In the base, the creation menu offers **New application** (if the AI chat is enabled and you are allowed to create applications). The editor opens with three tabs, **Preview**, **Code** and **Logs**, and the AI chat on the right: describe your application there, then refine it.

Clicking a block in the preview references it in the chat. **Edit text directly** corrects displayed text without going through a request. **History** lists the versions of the application; **Restore this version** goes back to the one you selected.

## Publishing

The **Publish** button, at the top of the editor, opens the **App publishing** panel. It offers two access modes, to choose from:

- **By invitation — invited people and base members** (suggested by default). Each person signs in with their TblFlow account, without a password: magic link or security key.
- **Public — anyone with the link**. A confirmation is requested: anyone who receives the link opens the app, without an account, and sees the data it displays.

**Allow data writes** is off by default. A read-only app cannot break anything; turn it on only if visitors really need to create or modify records from the app.

Clicking **Publish — generate the link** produces a URL immediately. There is no shared password and no visitor account specific to the application. Guests, page customization, unpublishing and custom domains are described in [Sharing and publishing](/en/docs/sharing-publishing).

## The code stays yours

A published application is real React and Tailwind code, not a black box: **Code → Export code** retrieves all of it. Conversely, **Import code** lets you start from an existing base to adjust it by hand after an AI generation.
