自动化是附属于某个数据库的工作流：一个触发器，后面跟着一系列步骤。它在服务器端运行，即使没有人打开标签页也照常执行。

## 触发器

| 触发器 | 触发时机 |
| --- | --- |
| 记录已创建 | 被监视的数据表新增了一行 |
| 记录已更新 | 被监视字段的值发生变化 |
| 记录符合条件 | 某一行进入了筛选器的范围 |
| Cron | 按给定的计划（cron 表达式，数据库时区） |
| Webhook | 有 HTTP 调用到达生成的 URL |
| 手动 | 有人点击了按钮字段 |

将“已更新”触发器限定在您真正关心的字段上，可以避免经典的死循环：自动化向它所监视的数据表写入，又触发了自己。

## 步骤

可用的步骤：创建 / 更新 / 删除记录、查找记录、发送邮件、调用 URL、运行条件分支、遍历列表、等待、请求审批、调用智能体。

每个步骤都会收到前面各步骤的输出。您用 `{{step.field}}` 来引用某个值，编辑器会列出在工作流的该位置真正存在的字段。

## 人工审批

**审批**步骤会暂停运行，并通知您指定的人员。批准后工作流继续，拒绝后停止，超过您设定的超时时间则过期。

请把它放在任何会对外发声的操作之前，例如发给客户的邮件、计费的 API 调用、对外发布。自动化在内部出错还可以纠正；一旦在客户那里出错，就很难挽回。

## 运行日志

每次运行都会连同其触发器、每个步骤的输入与输出以及任何失败的原因一并保留。修复原因之后，可以从日志重放失败的运行，而无需重新执行已经成功的步骤。

## 配额

每月的运行次数取决于套餐；Business 及以上套餐以及自托管时不限次数。无论包含多少个步骤，一次运行就是一次触发。

## 自动化还是智能体？

自动化执行的是您编写的序列：相同的输入、相同的路径、相同的结果。规则明确时，您需要的正是这个。

[智能体](/zh/docs/ai-agents)则根据目标自行决定步骤。当规则取决于内容时，您需要的是它，比如对各种不同的入站请求做分流。两者可以组合：自动化可以把智能体当作众多步骤中的一步来调用。
