自动化是附属于某个数据库的工作流：一个触发器，后面跟着一系列步骤。它在服务器端运行，即使没有人打开页面也会执行。

您可以点击**新建自动化**来创建，也可以用**AI 生成**描述您想要的效果：AI 会提出一份配置，您可以在编辑器中复核并调整。开关用于启用或停用自动化。在触发器配置完成之前，自动化无法启用。

## 触发器

| 触发器 | 触发时机 |
| --- | --- |
| **记录被创建时** | 所选数据表中新增了一行 |
| **记录被修改时** | 所选数据表中的某一行被修改 |
| **记录符合条件时** | 某一行满足您设定的全部条件（字段、运算符、值） |
| **记录被删除时** | 某一行被删除 |
| **表单被提交时** | 该数据表的某个表单被提交（指定某个表单视图，或全部表单） |
| **按钮被点击时** | 有人点击了该数据表的按钮字段（指定某个字段，或全部按钮字段） |
| **在计划时间** | 按您选择的间隔：分钟、小时、天、周或月 |
| **收到 Webhook 时** | 有 HTTP 调用到达编辑器中显示的 URL |
| **收到新邮件时** | 已连接的 Gmail 账户收件箱中出现新的未读邮件 |
| **连接器中出现新项目** | 连接器的某个列表中出现新项目 |
| **从界面触发** | 数据库生成的界面启动该自动化 |

补充说明：

- **定时。** 定时自动化按空间的时区运行；如果空间没有设置时区，则按 UTC 运行。默认情况下，间隔短于 15 分钟的设置会被拒绝。
- **Webhook。** 调用方式为 `POST`，且必须携带 `X-Webhook-Secret` 请求头。密钥在编辑器中设置；没有有效密钥，调用会被拒绝。收到的请求体可直接在变量的根层级读取。
- **收到新邮件。** 只有收件箱中新到达的未读邮件会触发自动化；启用自动化时已经存在的邮件会被忽略。Gmail 账户在**连接器**页面中连接。
- **触发链。** 写入其所监视数据表的步骤可能会重新触发该自动化。引擎会在连续五代之后切断这样的链，但最好把自动化设计为不依赖这种行为。

## 步骤

**添加步骤**菜单将步骤分为三类。

| 类别 | 步骤 |
| --- | --- |
| 借助 AI 构建 | **执行脚本**、**Slack**、**Microsoft Teams**、**发送邮件**、**AI 生成**、**创建、更新并获取记录**、**发送 HTTP 请求** |
| 手动构建 | **创建记录**、**获取记录**、**更新记录**、**按键创建或更新**、**运行 AI 字段**、**立即同步**、**操控网站** |
| 逻辑 | **如果满足条件**（**则**和**否则**分支）、**循环（对每一项）** |

**连接 API** 按钮会添加一个**调用已连接的 API**步骤，它依据第三方 API 的 OpenAPI 文档，执行该 API 的某个操作。

编辑器中没有删除记录、等待或人工审批步骤。如果需要在写入之前获得人工确认，请使用[智能体](/zh/docs/ai-agents)并开启写入审批。

每个步骤都可以读取触发器的数据以及前面步骤的输出。**插入变量**按钮列出在工作流的该位置真正可用的值。基本写法为：触发记录使用 `{{record.fields.<字段标识符>}}`，某个步骤的输出使用 `{{steps.<步骤标识符>.<路径>}}`。在 `|` 之后添加的过滤器可以转换某个值（日期、数字、列表、默认值、大小写）。出错的步骤会中断执行：后续步骤不会运行。

**发送邮件**步骤可以使用已连接的 Gmail 账户发送邮件；如果未选择账户，邮件将通过 TblFlow 的发送服务发出。

## 测试

**运行测试**会使用触发器的示例数据，对自动化进行一次不产生实际影响的试运行。弹窗会显示每个步骤的结果。提示语「这是模拟运行，没有任何真实数据被修改」会再次提醒您。测试会出现在历史记录中，状态为**测试**。

## 执行历史

**执行历史**按钮列出该自动化的执行记录，最近的排在最前。每条记录显示其状态（**成功**、**错误**、**进行中**或**测试**）、耗时、开始时间、触发器，以及每个步骤的类型、状态和备注。历史记录保留最近 50 次执行。历史中没有重新运行功能：修正问题后，请通过触发器重新启动自动化。

## 配额

每月的执行次数取决于套餐。每次触发计为一次执行，与步骤数量无关。自动化发送的邮件单独计算。

| 套餐 | 每月执行次数 | 每月自动化邮件数 |
| --- | --- | --- |
| 免费版 | 500 | 50 |
| Essential | 25,000 | 2,000 |
| 团队版 | 250,000 | 20,000 |
| 企业版 | 不限 | 不限 |

在自托管部署中，这些上限不会被强制执行。智能体的配额详见 [AI 智能体](/zh/docs/ai-agents)页面。

## 自动化还是智能体？

自动化执行的是您编写的步骤序列：相同的输入、相同的路径、相同的结果。当规则已经明确时，这正是您需要的。

[智能体](/zh/docs/ai-agents)则根据目标自行决定步骤。当规则取决于内容时，例如对各类不同的入站请求进行分流，这才是您需要的。两者可以组合使用：智能体可以借助其工具列出并启动您的自动化，但需受写入审批的约束。
