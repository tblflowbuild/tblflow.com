智能体是附属于某个数据库的自主工作者。它有目标、工具范围和记忆，并且产出的是提案，而不是直接写入。

## 选择模型提供商

模型按数据库配置，使用您自己的 API 密钥：OpenAI、Anthropic、Google Gemini、Azure OpenAI、DeepSeek、Mistral、Groq、Cohere、任何兼容 OpenAI 的端点，以及通过 Ollama 和 LM Studio 运行的本地模型。

自托管并使用本地模型时，数据库中的数据不会离开您的基础设施。

## 设置范围

范围是安全的关键所在。智能体只会获得与其声明意图相匹配的工具，例如数据表、界面、自动化、智能体、应用、测试数据。其他工具不在它的模式中，因此它无法调用，而且每个工具在执行时都会重新检查自己的授权。

同时也要限制可访问的数据表。负责客服分流的智能体没有理由接触薪资表。

## 提案

当智能体想要更改结构或数据时，它会发出一个**提案**：带有 id 的变更预览。在您接受之前，不会写入任何内容。

对于低风险的工作（丰富某个字段、套用标签），您可以允许在特定数据表上直接写入。请逐表决定，切勿全局开放。

## 记忆

智能体的记忆是一张由实体和关系组成的图谱，提取自它过去的运行，而不是对话记录。每个任务只重新加载相关的片段：智能体记得住，上下文成本却不会无限增长。

记忆可以查看和编辑。当智能体学到了错误的内容时，您修正的是这条记忆，而不是提示词。

## 调度

智能体可以按需运行、按计划（cron）运行，也可以作为[自动化](/zh/docs/automations)中的一个步骤被调用。每月的智能体运行次数取决于套餐。

## 行之有效的做法

- 每个智能体只有一个目标。一个“管理整个 CRM”的智能体会出错得杂乱无章；三个职责单一的智能体，出错时一目了然。
- 一开始所有操作都走提案，等您看清它会犯哪类错误之后，再改为直接写入。
- 保留日志：每次运行都会保留它的计划、工具调用和写入。
