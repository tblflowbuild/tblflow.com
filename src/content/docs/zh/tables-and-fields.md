TblFlow 的数据表就是真正的 PostgreSQL 表，字段就是真正的列。这就是为什么即使您从不离开界面，本页也同样有用：您在这里的选择，就是数据库中实际存在的东西。

## 字段家族

**普通值**：单行文本、长文本、数字、货币、百分比、日期、复选框、评分、邮箱、电话、URL。它们只存储您输入的内容，不多不少。

**受限值**：单选、多选、用户。选项在字段上定义，这使得分组和筛选值得信赖：“进行中”的两种写法不可能并存。

**关系型**：关联记录、查找、汇总、条件汇总。见下文。

**计算型**：公式（200 多个函数）、自动编号、创建时间、最后修改时间、创建者、最后修改者。它们不可编辑：写入时会重新计算。

**活动型**：附件、按钮、AI。AI 字段会调用数据库上配置的模型，并把答案写入单元格。

## 关联两个数据表

**关联记录**字段会在两个数据表之间建立关系。关系建立之后：

- **查找**从关联的数据表中取出一个字段（把公司名称带到联系人所在的行）；
- **汇总**对关联记录做聚合（对某客户的交易做 `SUM`，对某项目的任务做 `COUNT`）；
- **条件汇总**在一个子集上做同样的事（对阶段为“已赢单”的交易做 `SUM`）。

当源数据发生变化时，这三者都会重新计算，包括通过外部 SQL 客户端更改的情况。

## 公式

公式在字段上定义，并适用于每一行。可用的函数类别：文本、数值、日期、逻辑，以及对关联记录的聚合。

```
IF(
  AND({Stage} = "Won", {Amount} > 10000),
  "Key account",
  "Standard"
)
```

公式不能产生副作用：不能写入其他数据表，也不能发起网络调用。这类需求需要使用[自动化](/zh/docs/automations)。

## 在 Postgres 中的样子

每个数据库是一个 schema，每个数据表是一张物理表，每个字段是一个有类型的列。您可以让 `psql`、ORM 或 BI 工具连接同一个实例，直接读取您的数据：无需导出，没有同步层，也没有复制延迟。

实际的推论是：一份 `pg_dump` 就是一份完整的备份，并且可以在别处使用。这就是这里所说的“没有锁定”。

## 值得了解的几点

- 重命名字段只会更改其标签，不会更改公式所引用的标识：不会有任何东西被破坏。
- 更改字段类型会尝试进行转换，并就可能丢失的值向您发出警告。
- 删除字段会删除该列。该操作会被记录，但除了数据库的回收站之外，无法撤销。
